## 首页重构（精美炫酷落地页）

**目标**：把单调的首页改造成视觉冲击力强的落地页，并同步到 GitHub。

**技术选型**
- Next.js 16 App Router + 静态导出（`output: 'export'`，`basePath: '/blog'`）
- 样式方案：CSS Modules（`src/app/page.module.css`）承载页面专属样式 + `globals.css` 承载全局/共享样式（页脚、文章卡片）。
- ⚠️ **重要坑点**：`styled-jsx` 只能在客户端组件中使用。在 Server Component（如 `Footer.tsx`、`PostCard.tsx`）中使用会报 `Invalid import 'client-only'`，Turbopack 构建直接失败。**解决方案：把 Server Component 的 `<style jsx>` 抽到 `globals.css`**。只有 `Header.tsx`（标记了 `'use client'`）可继续用 styled-jsx。

**新增组件**（`src/components/`）
- `HeroBackground.tsx` — Canvas 粒子星空：粒子漂浮 + 近距离连线 + 鼠标引力 + 粒子高亮辉光；支持 `prefers-reduced-motion`。
- `HeroIntro.tsx` — 打字机循环文案（4 组词轮播）、徽章脉冲点、CTA 按钮、数据统计条。
- `Reveal.tsx` — IntersectionObserver 滚动显现包装组件，支持 `delay` 交错动画。
- `ToolCard.tsx` — 交互式作品卡：`onMouseMove` 写入 CSS 变量 `--mx/--my`，实现鼠标跟随的聚光边框 + 内辉光；`is-featured` 变体为横向大卡。

**首页结构**（`src/app/page.tsx`）
Hero → 精选作品（C-Utils 大卡）→ 学习工具网格（7 张）→ 最新文章 → CTA 面板 → Footer

**其他改动**
- `Header.tsx`：吸顶玻璃拟态、滚动后加深背景（`is-scrolled`）、顶部滚动进度条、多导航项（作品/文章/C-Utils）。
- `Footer.tsx`：品牌区 + 快捷链接 + 底部分栏。
- `PostCard.tsx`：日期胶囊、悬浮箭头、"阅读全文"，日期格式化为中文长日期。
- `layout.tsx`：`lang="zh-CN"`，补全 SEO metadata 与 OpenGraph。
- `globals.css`：细滚动条、`::selection` 配色、`:focus-visible` 焦点环、`html { scroll-behavior: smooth }`、reduced-motion 全局降级。

**验证**：`npm run build` 通过（6 个静态页面）。提交 `20f11c1`，已 push 到 `origin/master`，GitHub Actions 部署触发。

**注意**：仓库默认分支是 `master`（`.github/workflows/nextjs.yml` 监听 master，而 `deploy.yml` 监听 main——后者实际不会触发，属冗余文件）。推送后访问 https://zhuhairong.github.io/blog/

## 第二轮：修复「大箭头」渲染错误 + 首页样式架构重构（提交 `6fb1b43`）

**用户反馈**：首页不好看，有很多大箭头，显示错误。

**根因（重要）**：
1. 上一轮在 Client Component（`Header`）里用了 `styled-jsx`，其样式被注入到独立 CSS chunk。
2. 构建产物中残留了 dev 阶段的旧 CSS chunk `754026780cf84aab.css`（含旧版 `.tool-card` 规则），**后加载覆盖了新写的样式**。
3. 结果是 `.tool-card-arrow` / `.tool-card-head` 等规则全部丢失 → 图标 SVG 失去 `width/height` → SVG 按默认尺寸撑满容器 → **巨型箭头**。
4. 验证方式：对比线上 CSS 与源码，发现 CSS 里只有旧类 `tool-card`，10 个新类 `tool-card-*` 全部缺失。

**修复动作**：
- **彻底移除 styled-jsx**，改为全部走 CSS Module / `globals.css`。
- 新增 `src/components/icons.tsx`，所有图标组件强制带 `width`/`height` 属性（根本性防御）。
- 清理 `.next` 与 `out` 残留（Windows 下 `out` 被预览进程占用，需先停进程再用 Python `shutil.rmtree`）。
- 修复 `Reveal.tsx` 的 ESLint **error**：`react-hooks/set-state-in-effect`（effect 内同步 setState）。改为 `useState(() => typeof window !== 'undefined' && ...)` 惰性探测能力。
- 顺带修复文章详情页硬编码的 `YourUsername/YourRepo` 占位链接，补齐 Footer / 返回导航 / Markdown 排版（新增 `post.module.css`）。
- 移除 `layout.tsx` 里包裹 children 的 `container` class（与 Hero 全宽背景冲突），改由各页面自行控制。

**验证手段**（可复用）：
- `npx tsc --noEmit` → 无错误
- `npx eslint src` → 0 error（4 个 warning 在历史文件 `c-utils/page.tsx`）
- 脚本统计线上/产物 HTML 中 `<svg>` 是否都带 `width=` → 17/17 通过
- 用剥离 `/blog` 前缀的本地 Python 服务预览静态导出

**教训**：改样式后**必须检查 `out/_next/static/chunks/` 里 CSS 文件的数量与内容**，确认没有残留 chunk 覆盖。构建错乱时先清 `.next` + `out` 再排查代码。

## 第三轮：清理 lint warning + C-Utils 页面样式统一（提交 `8bae4b9`）

**1. ESLint 归零**
- 4 个 `no-unused-vars` warning 在 `c-utils/page.tsx`，是 `catch (e)` 里 `e` 未使用
- 改用 **可选捕获绑定**（optional catch binding，ES2019）：`} catch {`
- 结果：`npx eslint src` → **0 error 0 warning**

**2. C-Utils 页面重构**
- 新增 `src/app/c-utils/c-utils.module.css`，**把 43 处内联 `style={{}}`（约 200 条声明）全部迁出**
- 产物验证：`grep -c 'style="'` 剩余 156 个，但**布局类（padding/margin/display:flex）残留 = 0** ✅
  → 剩余的都是必须运行时的值：分类色标 `CATEGORY_COLORS[cat]`、Prism 语法高亮 token 色
- 语义化改进：模块卡片 `div[onClick]` → `<button type="button">`（支持键盘）；快速跳转 chip 移除 JS 手动操作 `e.currentTarget.style`，改由 CSS `:hover`
- 标签页从 4 段重复 JSX 合并为配置数组渲染
- **修了一个真实 bug**：GitHub 测试文件链接指向 `/blob/main/`，但仓库默认分支是 `master` → 链接 404。已改为常量 `BRANCH = 'master'`

**3. 关于 CSS chunk 数量的认知修正**
- 重构后 chunk 从 2 个变为 4 个，一度以为又是残留，实为**正常的按路由 code splitting**：
  - `27bdb…` = page.module.css（首页）
  - `87eab…` = c-utils.module.css
  - `f719d…` = post.module.css
  - `bbfe0…` = Geist 字体 `@font-face`
- 每个页面只加载自己那份（首页 → bbfe0+27bdb；c-utils → bbfe0+87eab）
- 判断残留的正确方法不是数数量，而是**看某个 CSS 是否在页面里被引用 + 内容是否含旧类**

**4. GitHub Pages 目录解析行为（重要，勿误判为 bug）**
- `/blog/c-utils` → **200**（canonical，Next.js 生成的形式）
- `/blog/c-utils/` → **404**
- 与本地 `python -m http.server` 的行为**相反**（本地是加斜杠才 200）
- 结论：GitHub Pages 对无扩展名路径不做补斜杠重定向，所以 `Link href="/c-utils"` 是正确写法，无需改动

**5. 本地预览端口注意**
- 端口 `4320` 被沙箱拦截（`WinError 10013`），改用 `4310` / `4330` 正常
- 用 `run_in_background` 直接跑 server 时，任务结束进程会被回收；**需要先 `sleep` 探测再 `present_files`**

**6. ⚠️ 发现并修复：工作区 `.github/` 目录丢失**
- 现象：`git status` 显示 ` D .github/workflows/nextjs.yml`，本地 `.github/` 整个目录不存在
- **但远程仓库完好**（GitHub API 确认 `nextjs.yml` 3335 bytes 在线），部署流程未受影响
- 处理：`git checkout -- .github/` 恢复，`git diff HEAD -- .github/` 验证与提交完全一致
- 推测原因：早前用 `rm -rf .next out` 或 Python `shutil.rmtree` 清理时，可能误伤了隐藏目录；也可能是编辑器/工具链行为
- **教训**：**绝不要对仓库根目录做批量删除**。清理构建产物只删明确的白名单（`.next`、`out`），且优先用 `git clean -nd` 预演
- **每次收尾前必须 `git status` 检查有无意外的 deletion 条目**，尤其 `.github/`、`.gitignore`、配置文件这类不被构建产物覆盖的文件
